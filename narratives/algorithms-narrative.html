Artifact Description

The artifact I selected is my AnimalShelter Python class, which was originally created during CS 340 Client/Server Development to perform create, read, update, and delete operations on animal records stored in MongoDB. I first enhanced this artifact for the software design and engineering category by improving validation, error handling, logging, dependency injection, and resource management. For Milestone Three, I built on that version and focused specifically on algorithms and data structures. The enhanced file, Enhanced_AnimalShelter_Algorithms.py, keeps the existing CRUD functionality while adding in-memory tools for sorting, searching, indexing, and summarizing shelter records.

Why I Selected the Artifact and How It Was Improved

I selected this artifact because it gave me a practical way to demonstrate algorithms and data structures inside a program that already solves a real data-management problem. Rather than adding algorithms that were disconnected from the purpose of the application, I added features that could be useful after animal records are retrieved from MongoDB. The first major enhancement is a custom merge sort that can order records by a selected field such as name, breed, or animal type. Merge sort performs consistently well even when the records are arranged differently. My implementation also creates a new sorted list, so the original order of the animal records is preserved.

I also added a binary search that works on records that have already been sorted. Instead of scanning every record one at a time, the algorithm repeatedly divides the search area in half. The binary search quickly narrows the list to find a matching record, and if several records have the same value, it takes a little additional time to collect and return all those matches. I designed it to return all records that match the requested value, which is useful when more than one animal has the same name or category.

This enhancement shows that I can choose an algorithm based on the way the data is organized and the type of lookup being performed. The data-structure enhancement uses a Python dictionary as an in-memory lookup index. The index organizes records into groups based on a selected field, such as animal type, so the program can usually find the needed group almost immediately. he index first organizes the animal records into groups, such as dogs and cats. Once those groups are created, the program can usually find a specific group almost immediately without searching through every record again. I used that same structure to create a frequency-count method for quickly summarizing categorical values. I also added read_sorted(), which connects the MongoDB read operation to the custom merge-sort algorithm. Together, these changes make the artifact more useful for analysis while clearly demonstrating sorting, searching, hashing, and the use of dictionaries and lists.

Course Outcome Coverage

This enhancement meets the primary course outcome I planned to address for the algorithms and data structures category: designing and evaluating computing solutions using algorithmic principles while considering the trade-offs involved in design choices. I did not simply add a sorting method; I considered when each approach would make sense. Merge sort performs reliably as the number of records grows, but it uses additional memory because it creates temporary lists while sorting the data. Binary search is much faster than a linear scan for repeated searches, but the records must already be sorted. A dictionary index makes repeated exact-key searches very fast on average, but it also uses extra memory to maintain the index. These trade-offs helped me think beyond whether an algorithm works and focus more on why I would choose one approach over another.

The work also supports the outcome related to using well-founded computing techniques and tools to deliver value. The algorithms are integrated with the existing AnimalShelter class rather than isolated classroom examples. I retained the earlier software-engineering improvements and added unit tests for the new behavior. In PyCharm, all eight algorithm and data-structure tests passed successfully, including tests for normal and reverse sorting, duplicate search results, dictionary indexing, frequency counts, validation, and sorting records returned from the database layer. I do not currently need to change my outcome-coverage plan, because the enhancement addresses the algorithmic outcome I intended while also strengthening the technical quality of the artifact.

Reflection

One of the most useful things I learned from this enhancement was that choosing an algorithm is not just about picking the one with the fastest performance rating. I also must consider memory use, complexity, the size of the data, and how the program will actually be used. The surrounding conditions matter. For example, binary search is efficient, but it only provides that advantage when the records are already sorted (PastPaperHero | Algorithms - Algorithm Design and Analysis, n.d.). A dictionary can make repeated lookups extremely fast, but building and storing the index has a memory cost.

I also had to think about whether sorting should happen in Python or in MongoDB. I intentionally used an in-memory custom merge sort for this capstone enhancement because it demonstrates my understanding of the algorithm. For a very large production dataset, however, a MongoDB server-side sort with an appropriate database index could reduce application memory usage and might be the better design choice.

The biggest challenge was adding the new functionality without undoing the improvements from the first enhancement. I wanted the algorithms to fit naturally into the existing class and still preserve validation, testability, and compatibility with the CRUD methods. Testing was especially important because the algorithms needed to handle duplicate values, reverse ordering, invalid input, and the interaction between database reads and in-memory sorting. Seeing all eight tests passed in PyCharm gave me confidence that the enhancement behaves as intended. Overall, this milestone helped me connect concepts such as time complexity, space complexity, searching, sorting, hashing, and data structures to a working application rather than treating them as separate theoretical topics.
