Databases

The Database enhancement focuses on strengthening the MongoDB side of the AnimalShelter artifact. The emphasis is on safer connection practices, validation, credential protection, query handling, and database design decisions while preserving the CRUD behavior established in the earlier milestones.

Database Enhancement Focus

The original CS 340 artifact successfully connected Python to MongoDB, but its database configuration and error handling were tightly coupled to the CRUD class. The enhanced design separates configuration, validates data before database operations, verifies the connection, and avoids placing literal production credentials in the portfolio source code.

Configuration
MongoDB connection settings are grouped in a dedicated immutable configuration object.
Credential Safety
Credential values are escaped before URI construction and real passwords are not published in the portfolio.
Validation
Invalid or empty CRUD inputs are rejected before a database operation is attempted.
Connection Verification
A MongoDB ping can confirm that the server is reachable during initialization.

Before and After: Database Configuration

The enhanced design moves MongoDB settings into a separate MongoConfig object. This reduces configuration logic inside the CRUD class and provides one place to manage host, port, authentication source, database, collection, TLS, and connection timeout settings. 

@dataclass(frozen=True)
class MongoConfig:
    username: str = ""
    password: str = ""
    host: str = "localhost"
    port: int = 27017
    auth_source: str = "admin"
    db_name: str = "aac"
    collection_name: str = "animals"
    tls: bool = False
    server_selection_timeout_ms: int = 5000

Credential Handling

The URI-building method safely escapes the username, password, and authentication source before inserting them into the MongoDB connection string. For the public ePortfolio, credentials should remain outside the repository and only placeholders or environment-based configuration should be shown. 

def build_uri(self) -> str:
    if self.username and self.password:
        username = quote_plus(self.username)
        password = quote_plus(self.password)
        auth_source = quote_plus(self.auth_source)

        return (
            f"mongodb://{username}:{password}@"
            f"{self.host}:{self.port}/"
            f"?authSource={auth_source}"
        )

    return f"mongodb://{self.host}:{self.port}"

Input Validation Before Database Operations

One database-focused improvement is rejecting unsafe or invalid values before they reach MongoDB. A shared validation method gives the CRUD operations consistent behavior and prevents empty update or delete filters from being treated as normal requests. 

@staticmethod
def _require_nonempty_dict(value, field_name):
    if not isinstance(value, dict) or not value:
        raise DataValidationError(
            f"{field_name} must be a non-empty dictionary."
        )
    return value

This matters especially for update and delete operations. Requiring a non-empty dictionary lowers the risk of unintentionally applying an operation more broadly than intended.

Connection Verification and Controlled Failure

The enhanced constructor creates the MongoDB client once, applies a server selection timeout, selects the configured database and collection, and can verify connectivity with ping. 

self.client = client or MongoClient(
    self.config.build_uri(),
    tls=self.config.tls,
    serverSelectionTimeoutMS=(
        self.config.server_selection_timeout_ms
    ),
)

self.database = self.client[self.config.db_name]
self.collection = self.database[
    self.config.collection_name
]

if verify_connection:
    self.client.admin.command("ping")

Database connection failures are converted into a DatabaseConnectionError while the underlying exception is preserved for debugging. This is clearer than allowing connection problems to surface unpredictably during a later CRUD operation.

Indexing and Efficient Query Access

What the Artifact Already Demonstrates

  • MongoDB CRUD operations through PyMongo.
  • Query filters and projections.
  • Optional result limits.
  • Configurable database and collection names.
  • Validation before update and delete operations.

Database Design Considerations

  • Indexes are most useful on fields searched or sorted frequently.
  • Indexes can improve reads but add storage and write overhead.
  • Database-side filtering reduces unnecessary data transfer.
  • Large datasets generally benefit from pushing appropriate work to MongoDB instead of processing every record in Python.

In this capstone, indexing awareness is part of the database enhancement because performance is not only a Python concern. The design decision must consider query frequency, dataset size, storage overhead, and the cost of maintaining indexes when records change.

Security Mindset

The database work contributes directly to the security course outcome by keeping sensitive configuration out of the public presentation, validating data before database operations, using explicit connection settings, and making failures visible through controlled exceptions and logging.

Skills Demonstrated

  • NoSQL database integration: Python and PyMongo are used to work with the AAC MongoDB collection.
  • Database configuration: connection settings are separated from application behavior.
  • Data integrity: input validation is performed before write and delete operations.
  • Query design: filters, projections, limits, and the role of database-side processing are considered.
  • Performance awareness: indexing trade-offs and efficient data access are evaluated.
  • Secure design: credential exposure and uncontrolled database operations are treated as design risks.

Course Outcome Connection
