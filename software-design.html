Software Design and Engineering

This enhancement transforms the original data-access class into a more maintainable, testable, and professional software component.

Artifact Description

The artifact I selected for this enhancement is my AnimalShelter.py CRUD module from CS 340 Client/Server Development.

I originally created it in October 2025 as part of the Grazioso Salvare animal-shelter dashboard project.

The module acts as the data-access layer between Python and a MongoDB database containing Austin Animal Center records. It provides create, read, update, and delete operations and was designed so the dashboard could work with MongoDB without putting database logic directly into the user-interface code.

I selected this artifact because it represents a project where several areas of computer science came together in one place: object-oriented Python, database connectivity, validation, exception handling, and support for a larger application.

Enhancement Summary

For my Software Design and Engineering enhancement, I improved the original AnimalShelter.py artifact developed in CS 340 Client/Server Development. The original program provided CRUD functionality for managing animal shelter records in MongoDB, but the enhancement focused on making the software more maintainable, secure, and professionally structured.

I refactored the code to improve configuration and connection management, removed duplicate database connection logic, centralized validation, added structured logging and custom exception handling, and improved resource management. I also introduced dependency injection so the class could be tested without requiring a live MongoDB connection. Supporting unit tests were created to verify key behaviors such as input validation, update operations, and safe deletion.

This enhancement demonstrates my growth in object-oriented programming, software design, testing, error handling, and maintainable code development. It also reflects a stronger security mindset by separating configuration concerns and reducing the risk of exposing sensitive database credentials. Overall, the revised artifact shows how I can take a working software solution and improve its structure, reliability, testability, and readiness for real-world use.

Skills Demonstrated

Object-oriented design, modular architecture, testing, documentation, secure configuration, and design trade-off evaluation.

Reflection

The biggest thing I learned from this enhancement is that improving software design is often about reducing coupling and making responsibilities clearer. My first instinct was to think of an enhancement as adding more features. Once I worked through the code, I realized that making the module easier to configure, test, troubleshoot, and safely close was just as important. Dependency injection was a good example. It required only a small change to the constructor, but it made it possible to test the class with a mock client instead of requiring MongoDB for every test. Separating the connection settings into a dataclass had a similar effect because it made configuration easier to validate and easier to move outside the source code.

The main challenge was improving the design without breaking the interface that the existing dashboard expects. I did not want the enhancement to become a completely different program just to show change, so I kept the original constructor arguments and the create, read, update, and delete method names while building the new design features around them. I also had to consider the trade-off between hiding errors and making the caller responsible for them. The original version often returned a default value when MongoDB raised an error. In the enhanced version, invalid input and database failures raise specific exceptions while logging useful diagnostic information. This requires the calling application to handle failures deliberately, but a failed database operation should not look the same as a legitimate query that returned no records. Overall, the enhancement moved me from asking only whether code works to thinking about whether it will remain dependable, understandable, and maintainable when someone else uses or modifies it.
