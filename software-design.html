Enhancement One

Software Design and Engineering

For Milestone Two, I enhanced my original CS 340 AnimalShelter CRUD module in the Software Design and Engineering category. The goal was not to change the purpose of the application, but to make the existing code easier to maintain, test, diagnose, and reuse.

View Full Enhanced_AnimalShelter.py View Original_AnimalShelter.py

Enhancement Overview

The original artifact already supported MongoDB create, read, update, and delete operations. My enhancement keeps those capabilities while improving the internal design. I introduced a separate configuration object, centralized validation, structured logging, custom exceptions, dependency injection, connection verification, and explicit resource management.

Maintainability
Configuration and validation are separated from CRUD logic.
Testability
An existing MongoDB client can be injected for unit testing.
Reliability
Invalid input and database failures now produce clear exceptions.
Resource Management
The class can safely close connections through a context manager.

Before and After: MongoDB Connection Design

One of the clearest issues in the original code was that the MongoDB client was created twice. The enhanced version creates the client once, centralizes configuration, supports dependency injection, and can verify the connection with a MongoDB ping.

Before: Original Connection

self.client = MongoClient(uri)

self.database = self.client[db_name]
self.collection = self.database[collection_name]

# Connect to MongoDB
self.client = MongoClient(uri, tls=tls)

self.database = self.client[db_name]
self.collection = self.database[collection_name]

The original constructor duplicated client creation, which added unnecessary complexity and made the class harder to test.

After: Enhanced Connection

self.client = client or MongoClient(
    self.config.build_uri(),
    tls=self.config.tls,
    serverSelectionTimeoutMS=self.config.server_selection_timeout_ms,
)

self.database = self.client[self.config.db_name]
self.collection = self.database[self.config.collection_name]

if verify_connection:
    self.client.admin.command("ping")

The enhanced constructor creates one client, supports an injected client for testing, applies a server-selection timeout, and optionally verifies the connection before the object is used.

Before and After: Validation and Error Handling

The original methods often returned False, 0, or an empty list when something failed. That behavior made an invalid input look similar to a valid operation that simply found no matching records. The enhanced version separates validation failures from database failures.

Before: Silent Failure

if not isinstance(document, dict) or not document:
    return False

...
except PyMongoError as exc:
    print(f"Create error: {exc}")
    return False

After: Explicit Validation and Exceptions

document = self._require_nonempty_dict(
    document, "document"
)

try:
    result = self.collection.insert_one(document)
    return bool(result.acknowledged)
except PyMongoError as exc:
    LOGGER.exception("Create operation failed.")
    raise AnimalShelterError(
        "Unable to create the animal record."
    ) from exc

This change improves debugging because the calling application can distinguish a validation problem from a MongoDB error. Structured logging also preserves diagnostic information without relying on scattered print() statements.

Key Enhancement: Reusable MongoDB Configuration

I added an immutable MongoConfig data class to keep connection settings together. Credential values are safely escaped before being placed into the MongoDB URI. 

@dataclass(frozen=True)
class MongoConfig:
    username: str = ""
    password: str = ""
    host: str = "localhost"
    port: int = 27017
    auth_source: str = "admin"
    db_name: str = "aac"
    collection_name: str = "animals"
    tls: bool = False

    def build_uri(self) -> str:
        if self.username and self.password:
            username = quote_plus(self.username)
            password = quote_plus(self.password)
            auth_source = quote_plus(self.auth_source)
            return (
                f"mongodb://{username}:{password}@"
                f"{self.host}:{self.port}/"
                f"?authSource={auth_source}"
            )
        return f"mongodb://{self.host}:{self.port}"

This reduces the amount of configuration logic inside the AnimalShelter class and makes future configuration changes easier to manage. It also demonstrates separation of concerns: configuration is responsible for describing the connection, while AnimalShelter remains responsible for data operations.

Key Enhancement: Resource Management

The enhanced class now knows whether it owns the MongoDB client. When it does, it can close the client explicitly. Context-manager support also allows the object to be used with Python's with statement. 

def close(self) -> None:
    """Close the MongoDB client when this object created the client."""
    if self._owns_client and self.client is not None:
        self.client.close()
        LOGGER.info("MongoDB client closed.")

def __enter__(self) -> "AnimalShelter":
    return self

def __exit__(self, exc_type, exc_value, traceback) -> None:
    self.close()

This is a small design change, but it improves lifecycle management and makes ownership of external resources more explicit.

Skills Demonstrated

  • Object-oriented design: responsibilities are separated into configuration, validation, connection management, and CRUD behavior.
  • Defensive programming: invalid inputs are rejected before MongoDB operations are attempted.
  • Exception design: custom exception classes communicate the type of failure to the calling application.
  • Logging: structured log messages replace console-only error reporting.
  • Dependency injection: an existing client can be supplied, making the class easier to unit test without a live MongoDB server.
  • Backward compatibility: the familiar AnimalShelter(username, password) constructor remains supported.

Why the Enhancement Matters

The enhanced version is not simply longer code. It is organized so that failures are easier to diagnose, dependencies are easier to test, configuration is easier to change, and resources are handled deliberately. These improvements move the artifact from a functional academic CRUD module toward a more maintainable software component.
