Software Design and Engineering

This enhancement transforms the original data-access class into a more maintainable, testable, and professional software component.

Artifact Description

The artifact I selected for this enhancement is my AnimalShelter.py CRUD module from CS 340 Client/Server Development.

I originally created it in October 2025 as part of the Grazioso Salvare animal-shelter dashboard project.

The module acts as the data-access layer between Python and a MongoDB database containing Austin Animal Center records. It provides create, read, update, and delete operations and was designed so the dashboard could work with MongoDB without putting database logic directly into the user-interface code.

I selected this artifact because it represents a project where several areas of computer science came together in one place: object-oriented Python, database connectivity, validation, exception handling, and support for a larger application.

Enhancement Summary

  • Refactor into smaller methods with clearer responsibilities.
  • Add type hints, docstrings, and consistent naming.
  • Add logging, structured exception handling, and input validation.
  • Move credentials out of source code.
  • Add unit tests and clearer separation between database and presentation layers.

Skills Demonstrated

Object-oriented design, modular architecture, testing, documentation, secure configuration, and design trade-off evaluation.

Reflection

The biggest thing I learned from this enhancement is that improving software design is often about reducing coupling and making responsibilities clearer. My first instinct was to think of an enhancement as adding more features. Once I worked through the code,
I realized that making the module easier to configure, test, troubleshoot, and safely close was just as important. Dependency injection was a good example. It required only a small change to the constructor, but it made it possible to test the class with a mock client instead of requiring MongoDB for every test. Separating the connection settings into a dataclass had a similar effect because it made configuration easier to validate and easier to move outside the source code.
