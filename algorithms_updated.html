Enhancement Overview

The original artifact could retrieve MongoDB records, but it did not demonstrate custom algorithms or purposeful in-memory data structures. The Milestone Three enhancement added a non-mutating merge sort, binary search, a dictionary-based lookup index, frequency counting, and a read_sorted() workflow that connects MongoDB query results to the custom sorting logic.

Merge Sort
Predictable O(n log n) sorting without changing the original record order.
Binary Search
O(log n) lookup on sorted data, with support for duplicate matches.
Dictionary Index
O(n) construction with average O(1) exact-key lookup.
Frequency Counting
Single-pass O(n) counting for fields such as animal type or breed.

Key Enhancement: Dictionary-Based Lookup Index

A Python dictionary provides a second search strategy for repeated exact matches. The index groups records under a selected key such as animal_type or breed. 

index = {}

for record in records:
    key = record.get(field)
    index.setdefault(key, []).append(record)

matches = index.get(target_value, [])

Building the index requires one pass through the records, or O(n). After the index is built, exact-key lookup is O(1) on average. This uses more memory than a simple scan, but it is useful when the application repeatedly searches the same dataset.

Design Trade-Offs

Custom In-Memory Processing

  • Clearly demonstrates algorithm and data-structure concepts.
  • Works with records already returned by MongoDB.
  • Useful for moderate datasets and repeated local analysis.
  • Requires additional application memory.

Database-Side Processing

  • Often preferable for very large production datasets.
  • Can reduce the amount of data transferred to the application.
  • Can use MongoDB indexes and server-side sort operations.
  • Does not demonstrate custom algorithm implementation as directly.
